# PeoplePolicy AI — مساعد سياسات الموارد البشرية (HR Policy Assistant)

> **تنبيه وإخلاء مسؤولية:** جميع السياسات والسيناريوهات والوثائق الواردة في هذا المشروع هي **سياسات تجريبية مصطنعة لأغراض المشروع التعليمي، وليست سياسة رسمية لأي جهة حكومية أو خاصة.** المساعد أداة استعلام معلوماتية فقط ولا يملك صلاحية اعتماد الإجازات أو تعديل السجلات.

---

## 1. نظرة عامة على المشروع (Project Overview)

**PeoplePolicy AI** هو تطبيق عملي متكامل (MVP) مبني وفق معايير هندسة الذكاء الاصطناعي التوليدي والأنظمة الوكيلة (Agentic AI). يقدم التطبيق مساعداً ذكياً موجهاً باللغة العربية للإجابة على استفسارات الموظفين حول سياسات الموارد البشرية في **شركة أفق التجريبية**، واحتساب رصيد الإجازات السنوية المتبقية والتحقق من أهليتها الحسابية بدقة متناهية.

يجمع المشروع بين:
1. **محرك استرجاع محلي (RAG Engine):** يعتمد على TF-IDF ومعالجة اللغة العربية وقياس تشابه جيب التمام (Cosine Similarity) مع بوابة شواهد معايرة.
2. **أداة بايثون مدققة ومحمية (`calculate_leave_balance`):** تعمل بحسابات دقيقة عبر `Decimal` وتتحقق بصرامة بواسطة `Pydantic` لمنع الأخطاء الحسابية والأرصدة السالبة.
3. **تكامل اختياري مع Google Gemini API:** لتوليد الإجابات المعتمدة مع إمكانية التبديل التلقائي إلى **الوضع المحلي الحتمي (Local Deterministic Mode)** في حال عدم توفر مفتاح API أو انقطاع الاتصال.
4. **واجهة مستخدم احترافية باللغة العربية:** مبنية باستخدام Streamlit ومصممة بالكامل باتجاه اليمين إلى اليسار (RTL) مع خطوط عربية عصرية (Cairo / Tajawal).
5. **مجموعة اختبارات وتقييم آلية (Evaluation Suite):** تشمل 12 حالة فحص تغطي الاسترجاع، دقة الأدوات، الأمان، والأسئلة الخارجة عن النطاق.

## 2. بيان المشكلة (Problem Statement)

تواجه إدارات الموارد البشرية تدفقاً مستمراً من الأسئلة المتكررة من الموظفين حول ساعات العمل، وضوابط العمل عن بُعد، وآلية رفع التقارير الطبية، بالإضافة إلى التردد والارتباك في حساب الرصيد المتبقي للإجازات وما إذا كان الطلب مؤهلاً للتقديم. 

يقدم **PeoplePolicy AI** حلاً مؤتمتاً يقدم إجابات موثقة تستند مباشرة إلى وثائق السياسات وتظهر رمز المصدر الرسمي (Source ID)، مع إجراء العمليات الحسابية من خلال أدوات برمجية موثوقة ومفصولة عن منطق النموذج اللغوي لضمان عدم حدوث أي هلوسة (Hallucination).

## 5. ضوابط الأمان والترخيص وحدود الوكيل (Security & Authorization Boundaries)

- **التمييز الدقيق بين الاستعلامات والطلبات التنفيذية:** يفرق النظام بدقة بين الأسئلة الاستعلامية المشروعة عن سياسة الاعتماد (مثل: *"ما خطوات اعتماد الإجازة؟"* أو *"من المسؤول عن اعتماد الإجازات؟"*) وبين محاولات الأمر بتنفيذ إجراءات إدارية (مثل: *"اعتمد إجازتي الآن وأرسل الموافقة للموارد البشرية"* أو استفسارات الصلاحية *"هل يمكنك اعتماد إجازتي؟"*).
- **الرفض الإجرائي الصريح (Explicit Action Refusal):** عند توجيه أمر تنفيذي غير مصرح به، يرجع المساعد رفضاً قاطعاً وصريحاً باللغة العربية يوضح أنه لا يمكنه اعتماد الإجازات، أو إرسال خطابات/إيميلات الموافقة، أو تعديل السجلات والبيانات الوظيفية.
- **عرض السياسة المرجعية دون استبدال الرفض:** يتم تضمين الشاهد المرجعي الرسمي من لائحة مسار اعتماد الإجازات (`HR-APPROVAL-005`) كمرجع نظامي يدعم الرفض، دون أن يحل شرح السياسة محل الرفض الصريح.
- **قائمة الأدوات البيضاء في بايثون (Backend Tool Allowlist):** الأداة الوحيدة المصرح بتنفيذها هي `calculate_leave_balance`. أي طلب لاستدعاء دوال خارجية غير مصرح بها (مثل `approve_leave` أو `delete_employee` أو `send_email`) يُرفض فوراً على مستوى الكود البرمجي بحالة `UNAUTHORIZED_TOOL` ولا يقتصر الضبط على موجه الأوامر (Prompt).
- **السجلات الرقابية الفنية الآمنة (Safe Audit Logs):** يتم تسجيل محاولات الإجراءات غير المصرح بها بحالة `REJECTED_UNAUTHORIZED` والمدة الزمنية واسم الإجراء المحظور دون تسريب أي بيانات شخصية أو مفاتيح API أو سلاسل تفكير داخلية.
- **حماية المخطط (Schema Validation):** تفعيل `extra="forbid"` و `strict=True` لرفض أي حقول إضافية غير متوقعة أو قيم غير رقمية كالأعداد الحقيقية غير المحدودة (NaN/Infinity) أو القيم المنطقية (Booleans).
- **الحد الأقصى للاستدعاءات:** يحدد النظام عدد استدعاءات الأدوات بـ 3 استدعاءات كحد أقصى لكل دورة طلب لمنع حلقات الاستدعاء اللانهائية.
- **الأسئلة الخارجة عن النطاق:** فحص استباقي للأسئلة العامة (مثل: "ما عاصمة فرنسا؟") ورفضها بأدب مع توجيه الموظف لنطاق الموارد البشرية.

## 6. متطلبات التثبيت والتشغيل (Installation & Setup)

### المتطلبات الأساسية
- نظام تشغيل: Windows أو macOS أو Linux
- بايثون الإصدار **Python 3.11+**

### خطوات التثبيت

1. **الانتقال إلى مجلد المشروع:**
   ```bash
   cd peoplepolicy-ai
   ```

2. **إنشاء وتفعيل بيئة افتراضية (مستحسن):**
   ```bash
   python -m venv venv
   # على أنظمة ويندوز (PowerShell):
   .\venv\Scripts\Activate.ps1
   # على أنظمة لينكس/ماك:
   source venv/bin/activate
   ```

3. **تثبيت الاعتماديات المطلوبة:**
   ```bash
   pip install -r requirements.txt
   ```

4. **إعداد ملف المتغيرات (اختياري):**
   قم بنسخ ملف `.env.example` إلى `.env`:
   ```bash
   copy .env.example .env    # ويندوز
   # أو
   cp .env.example .env      # لينكس / ماك
   ```
   - إذا كنت ترغب في تشغيل التطبيق في **الوضع المحلي الحتمي** بالكامل دون استخدام الذكاء الاصطناعي السحابي، اترك قيمة `GEMINI_API_KEY` فارغة.
   - إذا كنت ترغب في استخدام نموذج Gemini، ضع مفتاحك في الحقل:
     ```env
     GEMINI_API_KEY=AIzaSy...
     GEMINI_MODEL=gemini-2.5-flash
     ```

## 8. تشغيل الاختبارات الآلية (Automated Testing)

يحتوي المشروع على حزمة اختبارات شاملة باستخدام `pytest` بالإضافة إلى إمكانية تشغيلها مباشرة من داخل واجهة Streamlit.

### تشغيل الاختبارات عبر سطر الأوامر:
```bash
pytest -v
```

### حالات الفحص الـ 12 المعتمدة:
1. **استرجاع سياسة الإجازات السنوية:** استرجاع وثيقة `HR-LEAVE-001`.
2. **استرجاع سياسة الإجازات المرضية:** استرجاع وثيقة `HR-SICK-002`.
3. **استرجاع سياسة الحضور والدوام:** استرجاع وثيقة `HR-ATTEND-003`.
4. **استرجاع سياسة العمل عن بُعد:** استرجاع وثيقة `HR-REMOTE-004`.
5. **استرجاع مسار اعتماد الإجازات:** استرجاع وثيقة `HR-APPROVAL-005`.
6. **حساب الرصيد النموذجي:** رصيد 15 - طلب 6 = متبقي 9 (مؤهل).
7. **استنفاد الرصيد التام:** رصيد 5 - طلب 5 = متبقي 0 (مؤهل).
8. **عدم كفاية الرصيد:** رصيد 4 - طلب 10 = غير مؤهل، وحظر اعتماد رصيد سالب.
9. **رفض الأيام السالبة:** رفض إدخال عدد أيام مطلوبة بقيمة سالبة (-2).
10. **رفض حقول إضافية غير مصرح بها:** رفض حقول دخيلة على مخطط Pydantic (`extra="forbid"`).
11. **رفض أداة غير مصرح بها:** حظر استدعاء أداة `approve_leave` بقائمة الحظر البيضاء.
12. **معالجة الأسئلة الخارجة عن النطاق:** استبعاد سؤال "ما عاصمة فرنسا؟" والتأكيد على اختصاص الموارد البشرية.

## 9. مخرجات ونماذج تجريبية (Sample Outputs)

### مثال 1: استعلام وحساب رصيد إجازة
- **سؤال الموظف:**
  > "عندي رصيد 15 يوم إجازة، وأبي آخذ 6 أيام. هل أقدر؟ وكم يتبقى لي؟"
- **إجابة المساعد:**
  - **نتيجة الحساب:**
    - الرصيد المتاح: 15.0 يوماً
    - الأيام المطلوبة: 6.0 يوماً
    - الرصيد المتبقي المتوقع: 9.0 يوماً
    - حالة الأهلية: مؤهل حسابياً (نعم، يمكنك التقديم على الطلب).
  - **المرجع المعتمد:** وثيقة `HR-LEAVE-001` (سياسة الإجازات السنوية).
  - **التنبيه الإداري:** الأهلية الحسابية شرط للتقديم ولكنها لا تعني الموافقة الإدارية النهائية.

### مثال 2: استعلام عن ساعات الدوام وفترة السماح
- **سؤال الموظف:**
  > "ما هي مواعيد الدوام وساعات العمل الرسمية وفترة السماح؟"
- **إجابة المساعد:**
  - ساعات العمل الرسمية القياسية من 8:00 صباحاً حتى 4:00 مساءً من الأحد إلى الخميس بمعدل 40 ساعة أسبوعياً.
  - تمنح الشركة فترة سماح صباحية قدرها 15 دقيقة (حتى 8:15 ص) لاستيعاب الازدحام المروري.
  - **المصدر الرسمي المسترجع:** `HR-ATTEND-003` (سياسة الحضور وساعات العمل).

### مثال 3: سؤال خارج النطاق
- **سؤال الموظف:**
  > "ما عاصمة فرنسا؟"
- **إجابة المساعد:**
  - "عذراً، أنا مساعد ذكي مخصص حصرياً لسياسات الموارد البشرية وإجراءات الإجازات في شركة أفق التجريبية. لا يمكنني الإجابة على استفسارات عامة خارج هذا النطاق."

### مثال 4: طلب تنفيذ إجراء اعتماد محظور (Unauthorized Action Request)
- **سؤال الموظف:**
  > "اعتمد إجازتي الآن وأرسل الموافقة للموارد البشرية."
- **إجابة المساعد:**
  - **الرفض الصريح:** "⛔ رفض إجرائي — عملية غير مصرح بها: عذراً، بصفتي مساعداً ذكياً للموارد البشرية، لا يمكنني اعتماد طلبات الإجازة، أو إرسال رسائل أو موافقات إدارية، أو تعديل السجلات والبيانات الوظيفية في شركة أفق التجريبية. هذا النظام مخصص للمعلومات والاستعلامات وحساب الأرصدة فقط. يرجى تقديم طلب الإجازة عبر بوابة الخدمة الذاتية الرسمية..."
  - **الشاهد المرجعي:** وثيقة `HR-APPROVAL-005` (مسار اعتماد وتدفق الإجازات).
  - **السجل الرقابي:** تسجيل حالة `REJECTED_UNAUTHORIZED` للأداة المحظورة `approve_leave`.

### مثال 5: استعلام عن مسار وخطوات الاعتماد (Informational Query)
- **سؤال الموظف:**
  > "ما خطوات اعتماد الإجازة؟"
- **إجابة المساعد:**
  - شرح الخطوات الثلاث المعتمدة: (1. التقديم عبر بوابة الخدمة الذاتية، 2. مراجعة واعتماد المدير المباشر خلال 48 ساعة، 3. توثيق عمليات الموارد البشرية)، دون إصدار أي رفض، مع إرفاق وثيقة `HR-APPROVAL-005`.

## 10. المقارنة بين نمطي التشغيل (Local Mode vs. Gemini Mode)

| الخاصية | الوضع المحلي الحتمي (Local Mode) | وضع Gemini الذكي (Gemini Mode) |
| :--- | :--- | :--- |
| **مفتاح API** | غير مطلوب إطلاقاً (يعمل دون إنترنت) | يتطلب مفتاح Google Gemini API صالح |
| **محرك الاسترجاع** | TF-IDF مع تطبيع العربية وتماثل جيب التمام | TF-IDF مع تمرير الشواهد المعتمدة للنموذج |
| **تنفيذ الأدوات** | كود بايثون محلي دقيق مع Pydantic | كود بايثون محلي دقيق مع Pydantic |
| **صياغة الإجابة** | قوالب حتمية صارمة مبنية على الشواهد والأدوات | صياغة لغوية مرنة ومقيدة حرفياً بالشواهد |
| **الاعتمادية** | استقرار تام بنسبة 100% وبدون تكاليف | يعتمد على الاتصال بالإنترنت وحصة الاستخدام |
| **التحول التلقائي** | - | ينقلب آلياً إلى الوضع المحلي في حال حدوث أي خطأ |
